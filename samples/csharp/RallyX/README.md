# Rally-X for Screen9

> **Status: work in progress.** The maze, chasing enemies, flags, rocks, smoke, fuel, lives and rounds work, and an autopilot plays it.
> Still to do: tuning (speeds, chase behaviour and difficulty are not balanced against the arcade), mouse/touch control, a saved high
> score, proper sound effects, a closer camera. The art is the original Rally-X (Namco/Midway), used here for demonstration only.

A second C# game on the engine, after Gorillas: **Rally-X**, ported from the RallyX project (Phaser/JavaScript) to true pixel art and to the
engine's devices. Drive the blue car through the maze, collect the 10 flags, avoid the rocks and the red cars that chase you; smoke stops them.

## Usage

```powershell
dotnet run -c Release samples/csharp/RallyX/RallyX.cs                     # play (pixel window, Windows)
dotnet run -c Release samples/csharp/RallyX/RallyX.cs -- --sound          # with the speaker (Console.Beep)
dotnet run -c Release samples/csharp/RallyX/RallyX.cs -- --demo           # the autopilot plays by itself; any key quits
dotnet run samples/csharp/RallyX/RallyX.cs -- --selftest                  # three autopilot matches without a window (seed: RALLYX_SEED)
dotnet run -c Release samples/csharp/RallyX/RallyX.cs -- --smoke          # demo in the window, with checks
dotnet test src/RallyX.Tests
```

On the web site: page `/rally-x` (`dotnet run --project src/Screen9.Web`). There the game runs in the browser as WebAssembly (`RallyXGame.RunAsync`, awaiting the host's `Delay`
rather than sleeping); `Run()` is the same game for a window. For 30 fps use a published (AOT) build: see [docs/web](../../../docs/web/README.md).

| Key | Action |
|---|---|
| Arrows or WASD | drive (the turn happens as soon as it is possible; key repeat renews the request) |
| Space | smoke: 3 clouds, one per tile you leave, 1 fuel each; enemies that hit a cloud stop for 2.5 s |
| P | pause |
| Esc | back to the title; Esc on the title quits |

Rules: 100 fuel (about 83 s), 3 lives, one more enemy each round (up to 7). Flags score 100, 200, 300… in the order you take them; the
10th (marked S) doubles the value of that flag and of the following ones. When the last flag is taken the remaining fuel becomes points
(10 each) and the next round starts, keeping score and lives. A rock, an enemy or an empty tank destroys the car.

Without `-c Release` the engine code is not optimised and the game stutters (45 ms per frame against 5).
In the window the picture is enlarged by whole multiples only (`PixelWindow.IntegerScale`), so all pixels have the same size.

## How it is built

| File | What it does |
|---|---|
| `RallyXSim.cs` | the rules (from `solo.js`): rounds, flags, rocks, smoke, fuel, lives, score, explosion, end of round and of game. No devices: `Step()` advances 1/60 s and the match is driven with `Steer`/`DropSmoke` |
| `RallyXCar.cs` | the car (from `Car.js`): constant speed along the axes, turns only if its 16 px box fits the neighbouring corridor, picks another direction on hitting a wall, 12-frame turn animations |
| `RallyXWorld.cs`, `RallyXAssets.cs` | the 42×64 map (24 px tiles) and the indexed art |
| `RallyXRenderer.cs` | composes a 320×240 frame and doubles it to 640×480 (mode 12): 272×240 of field and 48×240 of HUD; radar at 3 px per tile |
| `RallyXGame.cs` | title → match → title at 30 frames per second with two simulation steps each; `RallyXHost` (screen, keyboard, time, sound) |
| `RallyXAutopilot.cs` | a driver (breadth-first search to the nearest flag, avoids enemies, drops smoke): demo and tests |
| `RallyX.cs` | the desktop launcher; the same game runs in the web page without duplication |

Frames are written with `PCCanvas.PutPixels` (new in the engine: block write with the same video memory as `PSet`, 5 ms for 640×480
against 45 ms for `PutImage` pixel by pixel).

## The art

The art is in `Assets/rallyx.assets` (140 KB), generated by `ops/build-rallyx-assets.py` from the RallyX project assets:

```powershell
python -I ops/build-rallyx-assets.py <path of the RallyX project> --preview $env:TEMP\rallyx     # requires Pillow
```

The converter brings the 4×-enlarged pixel art back to true resolution (24 px tiles, 16 px sprites), reduces game and HUD to one 16-colour
palette (nearby colours merged, with black, white, yellow, red, radar blue, HUD green, road sand, grass lime and score cyan fixed) and the
title to its own 16-colour palette, and checks that the tileset and the JSON map rebuild the exported map (0.4% of pixels differ, decorative
corners only). **The "Naonian Retrogaming Society" logo is not there**: it is removed from the title (which stays white above the RALLY-X
banner, where the game writes the instructions) and from the HUD (the last rows become black). Road and grass colours are the `ROAD` and
`GRASS` constants of the converter.

The Rally-X art and game design belong to Namco/Midway: they are used here for demonstration only, like Microsoft's GORILLA.BAS.

## Differences from the original project

- **Lives carry over** from round to round (in `solo.js` each round restarted with 3: it looks like an oversight, the score does carry over).
- The round ends when **no flags are left to take**: in `solo.js` the check counted the flags still in the dictionary, including caught ones
  waiting for their 3-second removal, so two flags taken less than 3 seconds apart left the round stuck.
- **Smoke** leaves three clouds, one per tile left (in the original the counter was reset at every frame and the three clouds ended up on the
  same tile); it is dropped with Space instead of Ctrl.
- The end-of-round **black curtain** stays closed until the next round (in the original it vanished for 2 seconds and the field reappeared).
- The camera starts already on the car (in the original it scrolled in from the map).
- There is **no mouse/touch**: keyboard only. The engine's INKEY$ has no "key released", so steering is a request that lasts half a second.
- The best score is not saved between sessions.
